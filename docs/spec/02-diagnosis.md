# 02. 진단 (6-1)

**흐름:** 진입 → 촬영 또는 앨범 선택(정밀 모드 선택 가능) → 품질 검사 → 분석(브라우저 내) → 결과 → 드레이핑, 카드 저장·공유 → 피드백 → (로그인 시) 이력 저장

**비로그인 허용.** 결과는 그 브라우저에 **수치와 톤 결과만** 임시 저장하고, 로그인하면 이력으로 옮길지 물어본다. (O-1)

## 품질 검사 (통과 / 경고 / 실패)
| 항목 | 처리 |
|---|---|
| 얼굴 1명 인식 | 실패 시 진행 차단 |
| 얼굴 크기, 각도 | 실패 시 진행 차단 |
| 밝기 (너무 어둡거나 과다 노출) | 실패 시 진행 차단 |
| 색 편향 (조명 색) | 경고 또는 차단 |
| 선명도 | 실패 시 진행 차단 |
| 보정·필터 의심 | 경고 + 신뢰도 하향 |
| 기준 수치 | **[미정]** 구현 중 샘플 사진으로 정한다 |

## 분석 파이프라인
① 얼굴 랜드마크 추출 → ② 피부·눈동자·머리카락 영역 샘플링(여러 영역의 **중앙값**) → ③ 조명 보정(정밀 모드면 흰 기준 사용) → ④ 특징값 계산(웜/쿨, 명도, 채도, 대비) → ⑤ 점수화 후 16톤 매핑 → ⑥ `ColorProfile` 생성

## 특징값 정의 (④) [임시 정의, M3 후 재검토]
> 가설이다. M3에서 샘플 사진·지인 피드백으로 검증하고 다시 정한다. (결정 로그 M1-Q1, M1-Q2. 코드: `packages/core/src/features.ts`)

- **입력(`ColorSample`):** 영역별 sRGB 값(0~255). **조명 보정(③)이 끝난 값**을 받는다. 피부(`skin`)는 1개 이상 필수, 머리카락(`hair`)·눈동자(`iris`)는 선택. 좌표·이미지 등 다른 필드는 받지 않는다(O-1, O-2).
- **대표값:** core가 영역별 값을 CIE Lab(D65)으로 바꾼 뒤, 영역들의 L\*·a\*·b\*를 **각각 중앙값**으로 묶는다(②).
- **warmCool** = 피부 대표색의 색상각 h°. **클수록 웜**(노란 쪽), 작을수록 쿨(붉은·분홍 쪽). 단위 °.
  - 세부(에이전트 제안): "클수록 웜"이 깨지지 않도록 −180°~180° 범위로 나타낸다. 예: 분홍 쪽으로 0°를 살짝 넘은 색은 355°가 아니라 −5°.
- **보조 값** `skinBStar` = 피부 b\*(노란기). 함께 계산만 해 두고, `ColorProfile`에는 넣지 않는다.
- **lightness** = 피부 L\*(0~100). **chroma** = 피부 C\*.
- **contrast** = 피부와 머리카락·눈동자의 밝기 차이 |ΔL\*|. 둘 다 있으면 두 차이의 평균(세부: 에이전트 제안). 하나만 있으면 그 값을 쓴다. **둘 다 없으면 `null`**.
- 무채색(C\* ≈ 0)은 C\* = 0, h° = 0으로 고정한다(결정성).

**정밀 모드:** 흰 종이나 흰 옷을 함께 촬영 → 흰 영역을 기준으로 보정 → 못 찾으면 일반 모드로 전환하고 이유 안내 → 성공 시 신뢰도 가산

## 16톤 구조 [확정] / 이름과 경계값 [미정, 튜닝 대상]
웜/쿨 × 명도 4단계(밝음, 중상, 중하, 어두움) × 채도 2단계(선명, 탁함). 4계절과 12톤은 16톤에서 **파생**한다.
| # | 톤 | 계열 | 명도 | 채도 |
|---|---|---|---|---|
| 1 | 봄 브라이트 | 웜 | 밝음 | 선명 |
| 2 | 봄 라이트 | 웜 | 밝음 | 탁함 |
| 3 | 봄 트루 | 웜 | 중상 | 선명 |
| 4 | 봄 소프트 | 웜 | 중상 | 탁함 |
| 5 | 가을 스트롱 | 웜 | 중하 | 선명 |
| 6 | 가을 뮤트 | 웜 | 중하 | 탁함 |
| 7 | 가을 딥 | 웜 | 어두움 | 선명 |
| 8 | 가을 딥뮤트 | 웜 | 어두움 | 탁함 |
| 9 | 여름 브라이트 | 쿨 | 밝음 | 선명 |
| 10 | 여름 라이트 | 쿨 | 밝음 | 탁함 |
| 11 | 여름 트루 | 쿨 | 중상 | 선명 |
| 12 | 여름 뮤트 | 쿨 | 중상 | 탁함 |
| 13 | 겨울 트루 | 쿨 | 중하 | 선명 |
| 14 | 겨울 소프트 | 쿨 | 중하 | 탁함 |
| 15 | 겨울 딥 | 쿨 | 어두움 | 선명 |
| 16 | 겨울 딥뮤트 | 쿨 | 어두움 | 탁함 |

현실에서 드문 칸(4, 8, 14, 16번)은 지인 데이터를 보고 합치거나 이름을 바꾼다. (코드: `packages/core/src/tone-config.ts`)

## 신뢰도 [계산식 미정]
구성 요소: ① 품질 플래그 수 ② 정밀 모드 여부 ③ 입력 방식(촬영 > 업로드) ④ 1순위와 2순위의 점수 차 ⑤ 샘플링 영역 간 일관성. 2순위는 항상 함께 보여준다.

## 결과 화면
톤 이름, 신뢰도, 2순위 / 품질 경고 배너 / 베스트·워스트 팔레트(색 이름 병기) / 톤 설명·가이드(**정적 텍스트**, 초안은 AI가 쓰고 **사람이 검수**) / 개인화 코멘트(Claude, **로그인 사용자만**) / 드레이핑 / 결과 카드 저장·공유(브라우저에서 생성, **기본은 사진 미포함**) / "코디 받기" / 피드백

**필수 문구:** "참고용이며 의학적 진단이 아니에요", "화면 설정에 따라 색이 다르게 보일 수 있어요", 야간 모드·블루라이트 필터 사전 안내(촬영 전)

**가상 드레이핑:** 얼굴 아래에 베스트/워스트 색을 번갈아 덮어 비교(브라우저, 서버 비용 0). 저장 이미지는 사용자 기기에만 저장한다.

**피드백:** ① 결과가 맞나요(맞아요/비슷해요/달라요) ② 실제 진단받은 톤(모름/선택) ③ 달랐다면 이유. 결과와 같은 ID로 연결한다.

**대표 진단 규칙:** 코디의 입력은 "대표 진단". 기본값은 **가장 최근 진단**이고, 마이페이지에서 다른 이력을 대표로 지정할 수 있다.
