# 02. 진단 (6-1)

**흐름:** 진입 → 촬영 또는 앨범 선택(정밀 모드 선택 가능) → 품질 검사 → 분석(브라우저 내) → 결과 → 드레이핑, 카드 저장·공유 → 피드백 → (로그인 시) 이력 저장

**비로그인 허용.** 결과는 그 브라우저에 **수치와 톤 결과만** 임시 저장하고, 로그인하면 이력으로 옮길지 물어본다. (O-1)

## 품질 검사 (통과 / 경고 / 실패)
| 항목 | 처리 |
|---|---|
| 얼굴 1명 인식 | 실패 시 진행 차단 |
| 얼굴 크기, 각도 | 실패 시 진행 차단 |
| 밝기 (너무 어둡거나 과다 노출) | 실패 시 진행 차단 |
| 색 편향 (조명 색) | 경고 또는 차단 |
| 선명도 | 실패 시 진행 차단 |
| 보정·필터 의심 | 경고 + 신뢰도 하향 |
| 기준 수치 | **[미정]** 구현 중 샘플 사진으로 정한다 |

### 품질 검사 규칙 (M2, 결정 로그 M2-Q1~Q6. 코드: `packages/core/src/quality*.ts`)
- **입력(`QualityMeasurements`):** 브라우저가 이미지에서 계산해 온 **측정값 숫자**만 받는다. core는 사진이나 브라우저 기능을 쓰지 않는다. 측정값마다 숫자 하나이고, **단위와 측정 방법은 M3에서 샘플로 정한다.** 측정하지 못한 값은 빼고 보낸다.

  | 측정값 | 항목 | 얼굴 기반 | 실패 기준 | 경고 기준 |
  |---|---|---|---|---|
  | `faceCount` | 얼굴 수 (0 이상 정수) | — | 정확히 1명이 아니면 실패 (고정 규칙) | 없음 |
  | `faceSize` | 얼굴 크기 | 예 | 하한·상한 [미정] | 꺼짐 (M3에서 켤지 결정) |
  | `faceAngle` | 얼굴 각도 | 예 | 하한·상한 [미정] | 꺼짐 (M3에서 켤지 결정) |
  | `brightness` | 밝기 (너무 어두움 / 과다 노출) | 아니오* | 하한·상한 [미정] | 꺼짐 (M3에서 켤지 결정) |
  | `colorCast` | 색 편향 (조명 색) | 아니오* | 하한·상한 [미정] | 하한·상한 [미정] (두 단계) |
  | `sharpness` | 선명도 | 아니오* | 하한·상한 [미정] | 꺼짐 (M3에서 켤지 결정) |
  | `filterSuspicion` | 보정·필터 의심 | 아니오* | **없음 (차단하지 않음)** | 하한·상한 [미정] |

  \* 얼굴 영역에서 재는지는 측정 방법(M3)에 따라 정한다. 설정의 `dependsOnFace`로 바꿀 수 있다.
  - **M3-1a 임시 정의 [M3-3에서 확정]:** `faceCount` = MediaPipe 가 찾은 얼굴 수(최대 2까지 찾음, 2는 "2명 이상"), `faceSize` = 랜드마크 외곽 상자 넓이 ÷ 이미지 넓이(0~1), `faceAngle` = 정면 대비 머리 회전각(°, 좌우·상하·기울기를 합친 하나의 각도, 0 이상). 코드: `apps/web/src/lib/diagnosis/face-regions.ts`
  - 하한·상한 각각 "숫자" 또는 "사용 안 함(`off`)"으로 정한다. **하나라도 미정(`null`)이면 판정 시 "미설정" 오류**가 난다. 실제 수치는 비워 두고 테스트에서만 임시 수치를 넣는다.
  - 경고 기준은 실패 기준보다 안쪽이어야 한다(경고가 먼저 걸리도록). 입력 방식(촬영/업로드)별로 기준을 나누지 않는다(필요하면 M3에서).
- **판정:** 측정값이 **경계값과 같으면 통과**. 하한 미만 → `_low`, 상한 초과 → `_high`. 실패 기준에 걸리면 실패, 아니면 경고 기준에 걸리면 경고, 아니면 통과.
- **측정 불가:** 얼굴 수가 실패이면 얼굴 기반 항목은 **건너뜀**. **보정·필터 의심은 측정 불가면 건너뜀**(진단을 막지 않음). 그 밖에 못 잰 항목은 **실패**.
- **전체 결과:** 실패가 하나라도 있으면 **실패**(진행 차단) / 실패 없이 경고가 있으면 **경고**(진행 가능) / 모두 통과(건너뜀 포함)면 **통과**. 보정·필터 의심이 경고이면 **신뢰도 하향** 표시.
- **`qualityFlags`에는 경고 이유 코드만** 남긴다(실패면 진단이 진행되지 않음).
- **O-2 적용 범위:** 얼굴 크기·각도 등 얼굴에서 나온 측정값은 **판정에만 쓰고 결과·저장소·로그 어디에도 남기지 않는다.** 판정 결과에는 이유 코드와 상태만 들어간다. 검사 오류 메시지에도 측정값 숫자를 넣지 않는다.

## 분석 파이프라인
① 얼굴 랜드마크 추출 → ② 피부·눈동자·머리카락 영역 샘플링(여러 영역의 **중앙값**) → ③ 조명 보정(정밀 모드면 흰 기준 사용) → ④ 특징값 계산(웜/쿨, 명도, 채도, 대비) → ⑤ 점수화 후 16톤 매핑 → ⑥ `ColorProfile` 생성

## 특징값 정의 (④) [임시 정의, M3 후 재검토]
> 가설이다. M3에서 샘플 사진·지인 피드백으로 검증하고 다시 정한다. (결정 로그 M1-Q1, M1-Q2. 코드: `packages/core/src/features.ts`)

- **입력(`ColorSample`):** 영역별 sRGB 값(0~255). **조명 보정(③)이 끝난 값**을 받는다. 피부(`skin`)는 1개 이상 필수, 머리카락(`hair`)·눈동자(`iris`)는 선택. 좌표·이미지 등 다른 필드는 받지 않는다(O-1, O-2).
- **영역(M3-1a) [임시, M3-3 재검토]:** 피부 = 이마·양 볼 3곳, 머리카락 = 이마 위쪽 3곳(턱→이마 방향으로 얼굴 높이의 12% 위), 눈동자 = 양쪽 홍채 고리(동공·흰자 경계 제외). 영역 중심이 사진 밖이면 그 영역은 뺀다. 브라우저 추출 결과는 **조명 보정(③) 전 값**이며, ③은 M3-2에서 core가 적용한다.
- **대표값:** core가 영역별 값을 CIE Lab(D65)으로 바꾼 뒤, 영역들의 L\*·a\*·b\*를 **각각 중앙값**으로 묶는다(②).
- **warmCool** = 피부 대표색의 색상각 h°. **클수록 웜**(노란 쪽), 작을수록 쿨(붉은·분홍 쪽). 단위 °.
  - 세부(에이전트 제안): "클수록 웜"이 깨지지 않도록 −180°~180° 범위로 나타낸다. 예: 분홍 쪽으로 0°를 살짝 넘은 색은 355°가 아니라 −5°.
- **보조 값** `skinBStar` = 피부 b\*(노란기). 함께 계산만 해 두고, `ColorProfile`에는 넣지 않는다.
- **lightness** = 피부 L\*(0~100). **chroma** = 피부 C\*.
- **contrast** = 피부와 머리카락·눈동자의 밝기 차이 |ΔL\*|. 둘 다 있으면 두 차이의 평균(세부: 에이전트 제안). 하나만 있으면 그 값을 쓴다. **둘 다 없으면 `null`**.
- 무채색(C\* < 0.001)은 C\* = 0, h° = 0으로 고정한다(결정성. 회색의 계산 오차는 최대 0.000018).
- 16톤 경계값은 [미정]으로 비워 두며, 비어 있는 채로 판정을 시도하면 "미설정" 오류가 난다(`requireToneThresholds`).

**정밀 모드:** 흰 종이나 흰 옷을 함께 촬영 → 흰 영역을 기준으로 보정 → 못 찾으면 일반 모드로 전환하고 이유 안내 → 성공 시 신뢰도 가산

## 16톤 구조 [확정] / 이름과 경계값 [미정, 튜닝 대상]
웜/쿨 × 명도 4단계(밝음, 중상, 중하, 어두움) × 채도 2단계(선명, 탁함). 4계절과 12톤은 16톤에서 **파생**한다.
| # | 톤 | 계열 | 명도 | 채도 |
|---|---|---|---|---|
| 1 | 봄 브라이트 | 웜 | 밝음 | 선명 |
| 2 | 봄 라이트 | 웜 | 밝음 | 탁함 |
| 3 | 봄 트루 | 웜 | 중상 | 선명 |
| 4 | 봄 소프트 | 웜 | 중상 | 탁함 |
| 5 | 가을 스트롱 | 웜 | 중하 | 선명 |
| 6 | 가을 뮤트 | 웜 | 중하 | 탁함 |
| 7 | 가을 딥 | 웜 | 어두움 | 선명 |
| 8 | 가을 딥뮤트 | 웜 | 어두움 | 탁함 |
| 9 | 여름 브라이트 | 쿨 | 밝음 | 선명 |
| 10 | 여름 라이트 | 쿨 | 밝음 | 탁함 |
| 11 | 여름 트루 | 쿨 | 중상 | 선명 |
| 12 | 여름 뮤트 | 쿨 | 중상 | 탁함 |
| 13 | 겨울 트루 | 쿨 | 중하 | 선명 |
| 14 | 겨울 소프트 | 쿨 | 중하 | 탁함 |
| 15 | 겨울 딥 | 쿨 | 어두움 | 선명 |
| 16 | 겨울 딥뮤트 | 쿨 | 어두움 | 탁함 |

현실에서 드문 칸(4, 8, 14, 16번)은 지인 데이터를 보고 합치거나 이름을 바꾼다. (코드: `packages/core/src/tone-config.ts`)

## 신뢰도 [계산식 미정]
구성 요소: ① 품질 플래그 수 ② 정밀 모드 여부 ③ 입력 방식(촬영 > 업로드) ④ 1순위와 2순위의 점수 차 ⑤ 샘플링 영역 간 일관성. 2순위는 항상 함께 보여준다.

## 결과 화면
톤 이름, 신뢰도, 2순위 / 품질 경고 배너 / 베스트·워스트 팔레트(색 이름 병기) / 톤 설명·가이드(**정적 텍스트**, 초안은 AI가 쓰고 **사람이 검수**) / 개인화 코멘트(Claude, **로그인 사용자만**) / 드레이핑 / 결과 카드 저장·공유(브라우저에서 생성, **기본은 사진 미포함**) / "코디 받기" / 피드백

**필수 문구:** "참고용이며 의학적 진단이 아니에요", "화면 설정에 따라 색이 다르게 보일 수 있어요", 야간 모드·블루라이트 필터 사전 안내(촬영 전)

**가상 드레이핑:** 얼굴 아래에 베스트/워스트 색을 번갈아 덮어 비교(브라우저, 서버 비용 0). 저장 이미지는 사용자 기기에만 저장한다.

**피드백:** ① 결과가 맞나요(맞아요/비슷해요/달라요) ② 실제 진단받은 톤(모름/선택) ③ 달랐다면 이유. 결과와 같은 ID로 연결한다.

**대표 진단 규칙:** 코디의 입력은 "대표 진단". 기본값은 **가장 최근 진단**이고, 마이페이지에서 다른 이력을 대표로 지정할 수 있다.
