# 02. 진단 (6-1)

**흐름:** 진입 → 촬영 또는 앨범 선택(정밀 모드 선택 가능) → 품질 검사 → 분석(브라우저 내) → 결과 → 드레이핑, 카드 저장·공유 → 피드백 → (로그인 시) 이력 저장

**비로그인 허용.** 결과는 그 브라우저에 **수치와 톤 결과만** 임시 저장하고, 로그인하면 이력으로 옮길지 물어본다. (O-1)

## 품질 검사 (통과 / 경고 / 실패)
| 항목 | 처리 |
|---|---|
| 얼굴 1명 인식 | 실패 시 진행 차단 |
| 얼굴 크기, 각도 | 실패 시 진행 차단 |
| 밝기 (너무 어둡거나 과다 노출) | 실패 시 진행 차단 |
| 색 편향 (조명 색) | 경고 또는 차단 |
| 선명도 | 실패 시 진행 차단 |
| 보정·필터 의심 | 경고 + 신뢰도 하향 |
| 기준 수치 | **[미정]** 구현 중 샘플 사진으로 정한다 |

### 품질 검사 규칙 (M2, 결정 로그 M2-Q1~Q6, M3-1b-Q1~Q4. 코드: `packages/core/src/quality*.ts`)
- **입력(`QualityMeasurements`):** 브라우저가 이미지에서 계산해 온 **측정값 숫자**만 받는다. core는 사진이나 브라우저 기능을 쓰지 않는다. 측정값마다 숫자 하나이고, **밝기만 숫자 두 개**(어두운 쪽·밝은 쪽 비율, M3-1b-Q2)다. 측정 방법은 아래 "측정 방법" [임시 정의]. 측정하지 못한 값은 빼고 보낸다.

  | 측정값 | 항목(설정 이름) | 얼굴 기반 | 못 재면 | 실패 기준 | 경고 기준 |
  |---|---|---|---|---|---|
  | `faceCount` | 얼굴 수 (0 이상 정수) | — | 실패 | 정확히 1명이 아니면 실패 (고정 규칙) | 없음 |
  | `faceSize` | 얼굴 크기 (`face_size`) | 예 | 실패 | 하한·상한 [미정] | 꺼짐 (M3에서 켤지 결정) |
  | `faceAngle` | 얼굴 각도 (`face_angle`) | 예 | 실패 | 하한·상한 [미정] | 꺼짐 (M3에서 켤지 결정) |
  | `brightnessDark` | 밝기: 어두운 쪽으로 뭉개진 비율 0~1 (`brightness_dark`) → `brightness_low` | 예 | 실패 | 상한 [미정] | 꺼짐 (M3에서 켤지 결정) |
  | `brightnessBright` | 밝기: 밝은 쪽으로 날아간 비율 0~1 (`brightness_bright`) → `brightness_high` | 예 | 실패 | 상한 [미정] | 꺼짐 (M3에서 켤지 결정) |
  | `colorCast` | 색 편향, 파랑(−)↔노랑(+) (`color_cast`) | 예* | **건너뜀** | 하한·상한 [미정] | 하한·상한 [미정] (두 단계) |
  | `sharpness` | 선명도 (`sharpness`) | 예 | 실패 | 하한·상한 [미정]. 상한은 M3-3에서 "사용 안 함" 후보 | 꺼짐 (M3에서 켤지 결정) |
  | `filterSuspicion` | 보정·필터 의심 (`filter_suspicion`) | 아니오 | **건너뜀** (경고만인 항목은 항상) | **없음 (차단하지 않음)** | 하한·상한 [미정] |

  \* 색 편향은 얼굴 **밖**을 재지만 얼굴 위치를 알아야 빼고 잴 수 있으므로 얼굴 기반이다. "얼굴 기반"(`dependsOnFace`)과 "못 재면"(`onUnmeasured`: `fail`/`skip`)은 항목별 설정으로 바꿀 수 있다(M3-1b-Q3).
  - **밝기를 두 숫자로 나눈 이유(M3-1b-Q2):** 하나로 합치면 어두운 쪽·밝은 쪽 문제가 서로 상쇄돼 나쁜 사진이 통과한다. 또 피부 밝기 자체가 아니라 **노출 문제(뭉개짐·날아감)**를 재므로 피부색이 어두운 사람이 막히지 않는다. 둘 다 문제면 둘 다 걸린다.
  - **M3-1a 임시 정의 [M3-3에서 확정]:** `faceCount` = MediaPipe 가 찾은 얼굴 수(최대 2까지 찾음, 2는 "2명 이상"), `faceSize` = 랜드마크 외곽 상자 넓이 ÷ 이미지 넓이(0~1), `faceAngle` = 정면 대비 머리 회전각(°, 좌우·상하·기울기를 합친 하나의 각도, 0 이상). 코드: `apps/web/src/lib/diagnosis/face-regions.ts`
  - **M3-1b 측정 방법 [임시 정의, M3-3에서 확정]** (코드: `apps/web/src/lib/diagnosis/quality-measure.ts`의 `MEASURE`). "얼굴 상자" = 랜드마크 외곽 상자(이미지 밖은 잘라냄). 얼굴 상자는 측정에만 쓰고 어디에도 남기지 않는다(O-2).
    - `brightnessDark` = 얼굴 상자 안에서 **세 채널 모두 16 이하**(검게 뭉개짐)인 픽셀 비율. `brightnessBright` = **한 채널이라도 250 이상**(하얗게 날아가 색 정보가 잘림)인 픽셀 비율. 눈동자·눈썹·상자 모서리의 배경도 들어가므로 기준값은 M3-3에서 이를 감안해 정한다.
    - `colorCast` = 얼굴 상자를 좌우·위로 25%, 아래로 60%(목) 넓힌 영역을 **뺀** 나머지에서, **L\* 70 이상·C\* 30 이하·어느 채널도 250 미만**인 픽셀(무채색에 가까운 밝은 픽셀)의 **b\* 중앙값**. 음수 = 파란 조명, 양수 = 노란 조명. 그런 픽셀이 측정 영역의 **1% 미만이면 측정 불가**(→ 건너뜀).
      - **한계:** ① 형광등 같은 **초록·자홍 편향은 잡지 못한다**(파랑↔노랑 한 축만 봄). ② 편향이 매우 강하면 흰 벽도 C\* 30을 넘어 기준 픽셀에서 빠지고 "측정 불가"가 될 수 있다. ③ 베이지 벽·피부색 배경처럼 원래 노란 물체가 기준 픽셀로 잡히면 노란 쪽으로 치우친다. 조명 보정(M3-2)과 같은 영역을 쓸지는 M3-2에서 정한다.
    - `sharpness` = 얼굴 상자를 회색조로 바꾸고 **긴 변 256px로 맞춘 뒤**(줄일 때 영역 평균, 키울 때 쌍선형) 라플라시안(4방향) 분산. 클수록 선명. 크기를 맞추므로 축소 상한과 무관하게 비슷한 값(가짜 무늬로 ±10% 이내 확인). **한계:** 얼굴 상자가 256px보다 작아 키워서 잴 때는 ±30% 정도 흔들린다. **실제 사진 실측(M3-1b, 13 "M3-1b 축소 상한 실측")에서는 원본 대비 최대 46%(2048)~76%(1280)~97%(512) 달라졌다** — 원본의 미세한 질감·잡음이 축소로 사라지기 때문. 따라서 **선명도 기준은 얼굴 상자를 고정 크기로 맞춘 값으로 M3-3에서 정한다**(결정 로그 M3-1b-상한확정). `sharpness_high`는 M3-3에서 "사용 안 함" 후보(M3-1b-Q4).
    - **측정 순서:** 모든 측정값과 영역 색은 **축소 상한을 적용한 이미지**에서 잰다. 상한은 **긴 변 1280px (PC 기준 잠정값, M3-3 샘플과 M4 실기기에서 재확인)** — 04 "성능 목표", 결정 로그 M3-1b-상한확정.
    - **상한 판단의 한계 (M3-1b 실측, 13):** 판단에 쓴 10장은 **결과를 본 뒤에 고른 것**이다. 옆얼굴·크게 돌린 얼굴·가림 3장을 뺀 근거는 "**상한을 키워도 차이가 줄지 않아 상한 문제가 아니라 피부 영역 문제**"라는 점이다. "그 3장이 품질 검사에서 걸러진다"는 **확인되지 않은 가정**이므로, M3-3에서 각도·가림 기준이 실제로 걸러내는지 확인하고 **안 걸러지면 피부 영역을 수정**한다.
    - **검출 재시도 [M3-2 후보]:** 원본 크기에서는 얼굴을 못 찾고 512에서만 찾은 사진이 1장 있었다 → 검출에 실패하면 더 작은 크기로 재시도하는 방안을 M3-2에서 검토.
    - `filterSuspicion`은 측정 방법이 정해지지 않아 **재지 않는다**(측정값에서 빠짐 → 건너뜀).
  - 하한·상한 각각 "숫자" 또는 "사용 안 함(`off`)"으로 정한다. **하나라도 미정(`null`)이면 판정 시 "미설정" 오류**가 난다. 실제 수치는 비워 두고 테스트에서만 임시 수치를 넣는다.
  - 경고 기준은 실패 기준보다 안쪽이어야 한다(경고가 먼저 걸리도록). 입력 방식(촬영/업로드)별로 기준을 나누지 않는다(필요하면 M3에서).
- **판정:** 측정값이 **경계값과 같으면 통과**. 하한 미만 → `_low`, 상한 초과 → `_high`(밝기는 `brightnessDark` 상한 초과 → `brightness_low`, `brightnessBright` 상한 초과 → `brightness_high`). 실패 기준에 걸리면 실패, 아니면 경고 기준에 걸리면 경고, 아니면 통과.
- **측정 불가:** 얼굴 수가 실패이면 얼굴 기반 항목은 **건너뜀**. 그 밖에 못 잰 항목은 **항목별 설정(`onUnmeasured`)대로 실패 또는 건너뜀**. 현재: **색 편향**(셀카 대부분에 기준 픽셀이 없을 수 있어 막지 않음, M3-1b-Q3)과 **보정·필터 의심**은 건너뜀, 나머지는 실패. (M2-Q4의 "그 밖은 실패"를 M3-1b-Q3에서 고침)
- **전체 결과:** 실패가 하나라도 있으면 **실패**(진행 차단) / 실패 없이 경고가 있으면 **경고**(진행 가능) / 모두 통과(건너뜀 포함)면 **통과**. 보정·필터 의심이 경고이면 **신뢰도 하향** 표시.
- **`qualityFlags`에는 경고 이유 코드만** 남긴다(실패면 진단이 진행되지 않음).
- **O-2 적용 범위:** 얼굴 크기·각도 등 얼굴에서 나온 측정값은 **판정에만 쓰고 결과·저장소·로그 어디에도 남기지 않는다.** 판정 결과에는 이유 코드와 상태만 들어간다. 검사 오류 메시지에도 측정값 숫자를 넣지 않는다.

## 분석 파이프라인
① 얼굴 랜드마크 추출 → ② 피부·눈동자·머리카락 영역 샘플링(여러 영역의 **중앙값**) → ③ 조명 보정(정밀 모드면 흰 기준 사용) → ④ 특징값 계산(웜/쿨, 명도, 채도, 대비) → ⑤ 점수화 후 16톤 매핑 → ⑥ `ColorProfile` 생성

### 조명 보정 (③) [방식 선택·숫자는 M3-3] (결정 로그 M3-D3, M3-2-Q4·Q5·Q7. 코드: `packages/core/src/lighting.ts`, 기준 통계: `apps/web/src/lib/diagnosis/quality-measure.ts`의 `measureLightingReference`)
- **두 방식:** "보정 안 함"(`none`)과 "회색 세계 가정"(`gray_world`). 어느 쪽을 쓸지(`LIGHTING_CONFIG.mode`)와 아래 숫자는 [미정]이며, 비어 있으면 "미설정" 오류가 난다. "보정 안 함"을 고르면 회색 세계 숫자는 필요 없다.
- **선형 색 공간에서 보정한다.** 감마가 걸린 sRGB 값(0~255)에 곱하지 않고, 선형값(0~1)으로 바꾼 뒤 채널별 배율을 곱하고 다시 sRGB로 돌린다. 조명은 빛의 세기에 곱해지는 것이므로 선형값에서 곱해야 맞다. 1을 넘는 선형값은 1로 자른다.
- **회색 세계 가정:** "기준 영역의 평균색은 무채색이다"라고 보고, 기준 영역 픽셀의 채널별 **선형값 평균** R̄·Ḡ·B̄로 배율 = (R̄+Ḡ+B̄)/3 ÷ 채널 평균을 구한다(전체 밝기는 대략 유지) [임시, M3-2-Q9 승인]. 피부·머리카락·눈동자 영역 색 모두에 같은 배율을 곱한다.
- **기준 영역 = 색 편향 측정과 같은 영역**(M3-2-Q4): 얼굴 상자를 좌우·위로 25%, 아래로 60% 넓힌 영역을 **뺀** 나머지. 피부가 보정을 끌고 가지 않게 하기 위해서다. 그 안에서 **한 채널이라도 250 이상인 픽셀은 뺀다**(색 정보가 잘림, 색 편향과 같은 규칙). 색 편향은 그중 "밝고 무채색에 가까운 픽셀"의 b\*만 보지만, 회색 세계 가정은 **영역의 모든 픽셀 평균**을 쓴다(채도 조건이 없다).
- **색 편향 측정과의 관계:** 둘 다 **보정 전 이미지**에서 잰다. 색 편향은 품질 검사(사진이 쓸 만한지)이고, 보정은 품질 검사를 통과한 뒤 영역 색에 적용한다. 색 편향을 못 재도(기준 픽셀 부족) 보정은 따로 시도한다.
- **"보정 안 함"으로 대체 + `lighting_fallback`** (회색 세계 가정을 골랐을 때만): ① 기준 통계를 못 잼(영역 없음, 채널 평균 0) ② 기준 영역 픽셀 수 ÷ 전체 픽셀 수 < `minAreaRatio` [미정] ③ 배율이 `maxGain` [미정]보다 크거나 1/`maxGain`보다 작음 — **잘라서 적용하지 않는다**(M3-2-Q7). `maxGain`은 "사용 안 함"(`off`)도 고를 수 있다. 설정에서 "보정 안 함"을 고른 경우는 대체가 아니므로 `lighting_fallback`을 붙이지 않는다.
- 브라우저는 기준 통계(채널별 선형 평균 3개와 영역 비율 1개)만 core에 넘긴다. 좌표·이미지는 넘기지 않고 `ColorProfile`에도 넣지 않는다(O-1·O-2). 정밀 모드(흰 기준)는 M5.

## 특징값 정의 (④) [임시 정의, M3 후 재검토]
> 가설이다. M3에서 샘플 사진·지인 피드백으로 검증하고 다시 정한다. (결정 로그 M1-Q1, M1-Q2. 코드: `packages/core/src/features.ts`)

- **입력(`ColorSample`):** 영역별 sRGB 값(0~255). **조명 보정(③)이 끝난 값**을 받는다. 피부(`skin`)는 1개 이상 필수, 머리카락(`hair`)·눈동자(`iris`)는 선택. 좌표·이미지 등 다른 필드는 받지 않는다(O-1, O-2).
- **영역(M3-1a) [임시, M3-3 재검토]:** 피부 = 이마·양 볼 3곳, 머리카락 = 이마 위쪽 3곳(턱→이마 방향으로 얼굴 높이의 12% 위), 눈동자 = 양쪽 홍채 고리(동공·흰자 경계 제외). 영역 중심이 사진 밖이면 그 영역은 뺀다. 브라우저 추출 결과는 **조명 보정(③) 전 값**이며, ③은 M3-2에서 core가 적용한다.
- **대표값:** core가 영역별 값을 CIE Lab(D65)으로 바꾼 뒤, 영역들의 L\*·a\*·b\*를 **각각 중앙값**으로 묶는다(②).
- **warmCool** = 피부 대표색의 색상각 h°. **클수록 웜**(노란 쪽), 작을수록 쿨(붉은·분홍 쪽). 단위 °.
  - 세부(에이전트 제안): "클수록 웜"이 깨지지 않도록 −180°~180° 범위로 나타낸다. 예: 분홍 쪽으로 0°를 살짝 넘은 색은 355°가 아니라 −5°.
- **보조 값** `skinBStar` = 피부 b\*(노란기). 함께 계산만 해 두고, `ColorProfile`에는 넣지 않는다.
- **lightness** = 피부 L\*(0~100). **chroma** = 피부 C\*.
- **contrast** = 피부와 머리카락·눈동자의 밝기 차이 |ΔL\*|. 둘 다 있으면 두 차이의 평균(세부: 에이전트 제안). 하나만 있으면 그 값을 쓴다. **둘 다 없으면 `null`**.
  - **용도 (결정 로그 회의-대비):** 계산해서 `ColorProfile.axes.contrast`에 저장하지만 **16톤 판정(1순위·2순위)에는 쓰지 않는다.** 이유: 머리카락 영역이 M3-1b 실측에서 축소 상한에 따라 원본 대비 ΔE2000 최대 약 24(512px)까지 흔들렸고(13 "M3-1b 축소 상한 실측"), 그 영역 문제를 풀기 전에 판정에 넣으면 정확도가 떨어질 수 있다. **M3-3에서 "대비를 넣었을 때 정확도가 좋아지는가"를 샘플로 비교한 뒤** 넣을지 결정한다. 결과 화면에서는 **참고 정보로만** 쓴다.
- 무채색(C\* < 0.001)은 C\* = 0, h° = 0으로 고정한다(결정성. 회색의 계산 오차는 최대 0.000018).
- 16톤 경계값은 [미정]으로 비워 두며, 비어 있는 채로 판정을 시도하면 "미설정" 오류가 난다(`requireToneThresholds`).

**정밀 모드:** 흰 종이나 흰 옷을 함께 촬영 → 흰 영역을 기준으로 보정 → 못 찾으면 일반 모드로 전환하고 이유 안내 → 성공 시 신뢰도 가산

### 12톤 대응표 (결정 로그 회의-12톤)
- 위 표의 "12톤 (파생)" 열이 대응표다. 12톤은 계절마다 3개(봄 브라이트·라이트·트루 / 여름 라이트·트루·뮤트 / 가을 트루·뮤트·딥 / 겨울 브라이트·트루·딥)이고, 16톤의 계절과 12톤의 계절은 항상 같다.
- **이 표는 우리 서비스의 설계안이며 업계 표준이 아니다.** 12톤 체계와 이름은 진단 기관마다 다르다. **최종 이름은 사람 검수 대상**이다.
- "확신 낮음"(4번→봄 트루, 14번→여름 뮤트)은 대응이 특히 불확실하다는 표시다. M3-3 샘플과 지인 피드백으로 다시 본다.
- 12톤은 **보여줄 때만** 쓰는 파생값이다. 판정·2순위·신뢰도는 16톤 기준으로 계산한다. 2순위 12톤도 `tone16_second`를 같은 함수(`toTone12`)로 바꿔 구하며 `tone12_second` 필드는 두지 않는다(M3-2-Q2). 1·2순위가 같은 12톤일 때 화면 표시는 M4.
- "확신 낮음"은 설정(`tone12LowConfidence`)에만 있고 `ColorProfile`에는 넣지 않는다(M3-2-Q3). 12톤 ID는 `계절_이름`(예: `winter_bright`), M6부터 동결.

### 드문 칸 (결정 로그 회의-드문칸)
현실에서 드문 칸(4, 8, 14, 16번)은 **지금 합치지 않고 16개를 유지**한다. 합칠지는 **M3-3 샘플 분포를 보고** 정한다. 12톤으로 보여줄 때만 위 대응표대로 합쳐 보인다. (코드: `packages/core/src/tone-config.ts`)

### 16톤 판정과 2순위 (⑤) [경계값·척도 미정] (결정 로그 M3-D5·M3-2-Q6. 코드: `packages/core/src/tone.ts`의 `judgeTone`)
- **판정에는 웜/쿨·명도·채도만** 쓴다. 대비는 쓰지 않는다(회의-대비).
- **경계와 같은 값은 "이상" 쪽**: `warmCool ≥ warmCoolSplit` → 웜, `chroma ≥ chromaSplit` → 선명, `lightness ≥ 경계` → 한 칸 밝은 쪽.
- **2순위 = 가장 애매했던 축의 이웃 칸.** 축마다 가장 가까운 경계까지의 거리를 그 축의 **척도**(`secondScale`, [미정] 설정값, M3-3)로 나눠 비교하고, 가장 작은 축의 경계를 건넌 칸을 2순위로 한다. 2순위는 항상 1순위와 **한 축만 한 칸** 다르다.
- **동점이면 웜/쿨 > 명도 > 채도** 순서로 고른다(웜/쿨이 조명에 가장 흔들리고 틀리면 가장 치명적, M3-2-Q6).
- 명도는 경계가 둘일 수 있어 가까운 쪽 이웃을 고르고, 두 경계까지 거리가 같으면 어두운 쪽을 고른다 [임시, M3-2-Q9 승인]. 맨 끝 칸(밝음·어두움)은 경계가 하나뿐이다.
- 경계값과 척도가 하나라도 비어 있으면 "미설정" 오류가 난다. 축별 거리(÷척도)는 신뢰도 ④에만 쓰고 결과에는 저장하지 않는다.

```
축마다 "가장 가까운 경계까지 거리"를 그 축의 척도로 나눠 비교
  웜/쿨  dW = |h° − warmCoolSplit| / 척도W
  명도   dL = (가까운 쪽 경계까지 |L* − 경계|) / 척도L
  채도   dC = |C* − chromaSplit| / 척도C
→ 가장 작은 축에서 그 경계를 건넌 칸이 2순위 (동점: 웜/쿨 > 명도 > 채도, 대비는 쓰지 않음)

명도:  어두움 | 중하 | 중상 | 밝음
             c1    c2    c3
예) 1순위 13 겨울 트루(쿨·중하·선명)
    · 명도가 가장 애매하고 c2에 더 가까움 → 11 여름 트루
    · 명도가 가장 애매하고 c1에 더 가까움 → 15 겨울 딥
    · 채도가 가장 애매함                  → 14 여름 소프트
    · 웜/쿨이 가장 애매함                 → 5 가을 스트롱
```

## 신뢰도 [계산식 미정]
구성 요소: ① 품질 플래그 수 ② 정밀 모드 여부 ③ 입력 방식(촬영 > 업로드) ④ 1순위와 2순위의 점수 차 ⑤ 샘플링 영역 간 일관성. 2순위는 항상 함께 보여준다.

**계산 구조 (M3-2, 결정 로그 M3-D4·M3-2-Q8. 코드: `packages/core/src/confidence.ts`)** — 가중치와 척도는 [미정](M3-3). 비어 있으면 "미설정" 오류.
- 다섯 요소를 각각 0~1 점수(클수록 믿을 만함)로 바꾼 뒤 **가중 평균**한다(결과 0~1). 요소별 점수 [임시 정의, M3-3 재검토]:

  | 요소 | 입력 | 점수 |
  |---|---|---|
  | ① 품질 플래그 | `qualityFlags` 개수 (**`lighting_fallback`·보정 의심 경고 포함**) | 1 / (1 + 개수) |
  | ② 정밀 모드 | `calibrationMode` | 정밀 1, 일반 0 |
  | ③ 입력 방식 | `inputType` | 촬영 1, 업로드 0 |
  | ④ 1·2순위 차이 | 16톤 판정의 축별 거리(÷척도) 중 가장 작은 값 = 2순위 축까지의 거리 | 거리 / (1 + 거리) |
  | ⑤ 영역 간 일관성 | **피부 영역(이마·양 볼)끼리의 최대 ΔE2000** (`skinSpread`) | 1 / (1 + 차이 ÷ `consistencyScale`). 피부 영역이 1개뿐이라 확인할 수 없으면 0 [임시] |
- **넣지 않는 것:** 대비(판정에 안 쓰므로), 12톤 "확신 낮음"(보여줄 때만 쓰는 파생값이므로) (M3-2-Q8).
- **⑤는 피부 영역 문제(13 [M3-2 숙제])를 잡는 도구다.** 한쪽 볼이 손에 가리거나 얼굴 경계에 걸리면 피부 영역끼리 차이가 커져 신뢰도가 내려간다. M3-3에서 가림 사진의 값을 함께 본다.
- 요소별 점수와 축별 거리는 `ColorProfile`에 넣지 않는다(신뢰도 숫자 하나만 저장).

(코드: `packages/core/src/types.ts`)
- `season4`는 1순위 16톤 이름의 앞글자, `tone12`는 1순위 16톤을 12톤 대응표로 바꾼 값이다(별도 계산 없음). `axes.contrast`는 저장만 하고 판정에는 쓰지 않는다(위 "contrast" 용도).
- **생성 (M3-2, 코드: `packages/core/src/profile.ts`의 `buildColorProfile`):** 품질 결과 → 조명 보정(③) → 특징값(④) → 16톤 1·2순위(⑤) → 신뢰도 → `ColorProfile`(⑥). 품질 결과가 **실패면 만들지 않는다.** `qualityFlags` = 품질 경고 코드 + (보정이 대체됐으면) `lighting_fallback`. `createdAt`은 호출하는 쪽이 시간대 있는 ISO 8601로 넣는다(core는 시계를 쓰지 않음, 결정성). 정밀 모드는 M5.
- **넣지 않는 것 (O-2):** 좌표·얼굴 측정값, 조명 기준 통계, 판정 중간값(축별 거리, 신뢰도 요소별 점수), 12톤 "확신 낮음", `tone12_second`.

## 결과 화면
톤 이름, 신뢰도, 2순위 / 품질 경고 배너 / 베스트·워스트 팔레트(색 이름 병기) / 톤 설명·가이드(**정적 텍스트**, 초안은 AI가 쓰고 **사람이 검수**) / 개인화 코멘트(Claude, **로그인 사용자만**) / 드레이핑 / 결과 카드 저장·공유(브라우저에서 생성, **기본은 사진 미포함**) / "코디 받기" / 피드백

**필수 문구:** "참고용이며 의학적 진단이 아니에요", "화면 설정에 따라 색이 다르게 보일 수 있어요", 야간 모드·블루라이트 필터 사전 안내(촬영 전)

**가상 드레이핑:** 얼굴 아래에 베스트/워스트 색을 번갈아 덮어 비교(브라우저, 서버 비용 0). 저장 이미지는 사용자 기기에만 저장한다.

**피드백:** ① 결과가 맞나요(맞아요/비슷해요/달라요) ② 실제 진단받은 톤(모름/선택) ③ 달랐다면 이유. 결과와 같은 ID로 연결한다.

**대표 진단 규칙:** 코디의 입력은 "대표 진단". 기본값은 **가장 최근 진단**이고, 마이페이지에서 다른 이력을 대표로 지정할 수 있다.
