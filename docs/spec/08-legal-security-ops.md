# 08. 개인정보·법무 · 보안 · 운영 (11~13)

> 법령 관련 내용은 **일반 정보이며 법률 자문이 아니다.** 3단계 전에 전문가 검토 1회 필수.

## 개인정보·법무 규칙
| ID | 규칙 |
|---|---|
| P-1 | 얼굴 데이터를 식별·인증·얼굴 비교에 쓰지 않는다. (약관 명시) |
| P-2 | 랜드마크 좌표, 얼굴 특징값은 저장하지 않는다. |
| P-3 | 진단은 브라우저에서만 처리한다. |
| P-4 | 사진을 외부로 보내는 기능(가상 피팅)은 별도 동의 + 별도 문서를 둔다. |
| P-5 | 가입 시 만 14세 이상 체크 필수. 14세 미만이 확인되면 계정·데이터를 삭제한다. |
| P-6 | 소셜 로그인 수집 항목 최소화. 공급자별 제공 항목·심사 조건은 구현 시 확인. |
| P-7 | Claude 프롬프트에 이름, 이메일, 사진, 사용자 ID를 넣지 않는다. |
| P-8 | 위탁 업체와 국외 처리 여부를 처리방침에 공개. 국외이전 요건 [확인필요] |
| P-9 | 업체를 바꾸면 처리방침도 같은 변경 단위로 갱신한다. |
| P-10 | 마이페이지에서 열람·삭제·탈퇴를 셀프 처리할 수 있게 한다. |
| P-11 | 탈퇴 시 개인 데이터 전부 삭제(결제 기록만 분리 보관). 백업은 최근 N개만 유지. |
| A-1 | 약관과 코디·피팅 화면에 "생성형 AI 사용" 사전 고지. |
| A-2 | 가상 피팅 결과 저장·공유 시 "AI 생성" 가시적 워터마크 자동 삽입. |
| A-3 | 코디 결과를 내보낼 때 "AI 추천" 문구 포함. |
| A-4 | "참고용이며 의학적 진단이 아님" 문구를 결과 화면에 둔다. |
| C-1 | 크레딧 구매의 미사용 잔액 추적. |
| C-2 | 구매 전에 환불 정책을 명확히 표시. |
| C-3 | 구독 해지를 마이페이지에서 쉽게. |
| C-4 | 크레딧 유효기간은 전문가 검토 후 결정. (3단계) |
| R-1 | 제휴 링크에 라벨. |
| R-2 | 쇼핑몰 이미지를 수집·저장하지 않는다. 업로드 이미지 권리는 사용자 책임임을 약관에 명시. |
| R-3 | 본인 사진만 업로드하도록 약관에 명시하고 신고 경로를 둔다. |
| R-4 | 마케팅 발송은 선택 동의 후에만. (1단계는 발송 안 함) |

**근거 요약(일반 정보):** 일반 얼굴 사진은 개인정보이나 식별·인증 목적의 특징정보 처리가 아니면 민감정보로 보지 않는다는 해석이 있다(최신 기준은 전문가 확인). 만 14세 미만은 법정대리인 동의 필요. AI 기본법(2026-01-22 시행)은 생성형 AI 사전 고지와 외부 유통 시 AI 생성물 표시를 요구. 디지털 콘텐츠도 통신판매업 신고·청약철회 규정 적용 대상일 수 있다.

## 보안 규칙 (퍼블릭 저장소 전제)
- **S-1** 키·비밀은 코드와 커밋 이력에 절대 포함하지 않는다. `.env` 계열은 `.gitignore`에 기본 포함.
- **S-2** 비밀 유출 자동 탐지와 커밋 전 검사를 켠다. 유출 시 즉시 폐기·재발급. (구체 설정은 구현 때 공식 문서 확인. 뼈대에는 간이 `scripts/check-secrets.mjs`가 있으며 GitHub secret scanning 등 정식 도구를 대체하지 않는다.)
- **S-3** 공개 키와 서버 전용 키를 이름부터 구분. 모든 테이블 RLS.
- **S-4** 서버 요청은 인증 → 권한(`canUse`) → 입력 검증 → 처리 순서.
- **S-5** 이미지 입력(형식, 크기, 얼굴 1명)을 서버 계층에서도 재검증.
- **S-6** 자유 입력(상황)은 길이·문자 검사, Claude 출력은 JSON 구조와 팔레트로 검증.
- **S-7** 요청 속도 제한과 예산 차단기를 서버 계층에.
- **S-8** 로그에 이미지, 프롬프트 원문, 토큰을 남기지 않는다. 오류 로그 마스킹.
- **S-9** 의존성 취약점 자동 점검(Dependabot 설정됨). 새 패키지는 이유와 라이선스 기록.
- **S-10** 서버 계층은 허용한 출처(CORS)에서만 호출.
- **S-11** 에이전트는 시크릿 파일을 읽거나 출력하지 않는다.
- **S-12** 카드 정보 입력은 PG·스토어 화면에서만.

## 운영
| 항목 | 방침 |
|---|---|
| 문의 | **서비스 전용 이메일 [준비 필요]**. 개인정보 요청을 공개 GitHub Issues로 받지 않는다 |
| 삭제·열람 | 마이페이지 셀프 + 이메일 백업 경로 |
| 장애 | 상태 확인·복구 순서(Supabase 일시정지 복구 등)를 운영 체크리스트에 |
| 백업 | 월 1회 내보내기, 최근 N개 유지 |
| 모니터링 | `usage_events`로 호출량·예산 사용률 확인 |
| 변경 관리 | 기준값·프롬프트·팔레트 변경은 `configVersion`과 변경 이유 기록 |
| 콘텐츠 | 16톤 설명·가이드는 AI 초안 → 사람 검수 → 반영 |
| 사고 대응 | 키 폐기 → 범위 파악 → 사용자 고지. 구체 요건 [확인필요] |

**단계별 필수 문서·조치**
- **1단계:** 간이 개인정보 처리방침, 이용약관(베타), 만 14세 이상 체크, AI 사전 고지, "참고용" 문구, 탈퇴·삭제 기능, 문의 이메일, 비밀 유출 방지 설정, noindex
- **2단계:** 사진 외부 전송 별도 동의서, 업체 약관·데이터 정책 확인, AI 생성 워터마크, 타인 사진 금지 약관·신고 경로, 처리방침에 위탁·국외 처리 추가, 만 19세 이상 체크
- **3단계:** **전문가 검토 1회**(개인정보, 소비자법, 제휴 표시), 통신판매업 신고 필요 여부·사업자등록증 업종 확인, 사이트 사업자 정보 표시(주소 노출 방법 포함), 환불·구독 해지 정책, 호스팅 전환, 앱 스토어 정책·수수료 재확인, 마케팅 수신 동의, 제휴 라벨, 미성년자 결제 방침, **서비스 이름의 도메인·앱 스토어 이름·상표 충돌 확인**
