# 07. 마일스톤과 에이전트 작업 규칙 (14)

## 에이전트 규칙
| ID | 규칙 |
|---|---|
| G-1 | 작업 전에 해당 섹션을 읽는다. **모순이나 빈틈을 발견하면 구현을 멈추고 기획자에게 보고** |
| G-2 | 한 마일스톤은 작게 끝낸다. **완료 기준은 착수 시 에이전트가 제안하고 기획자가 승인** |
| G-3 | `packages/core` 로직은 "추출된 색 수치" 입력 샘플로 만든 **자동 테스트** 필수 |
| G-4 | 새 패키지는 이유와 라이선스 기록. 비상업 라이선스 금지 |
| G-5 | 시크릿 파일 접근·출력, 코드 내 비밀 하드코딩 금지 |
| G-6 | 서비스 이름, UI 문구, AI 고지 문구는 한 곳(설정/문구 파일)에서 관리 |
| G-7 | 스위치, 쿼터, 예산 차단기를 우회하는 코드 금지 |
| G-8 | [확인필요] 항목은 구현 전 공식 문서로 확인하고 결과 기록 |
| G-9 | 기획 결정이 필요한 사안은 추정으로 진행하지 않고 질문 |
| G-10 | 변경이 지침서에 영향을 주면 갱신안과 결정 로그 항목을 함께 제안 |

### M3-1b 범위와 완료 기준 (승인 2026-10-15, 결정 로그 M3-1b-범위)
**범위:** ① 밝기·색 편향·선명도 측정 함수(web, 픽셀만 받는 순수 함수) ② 보정·필터 의심은 측정 방법이 없으므로 측정값에서 빼고 "건너뜀" ③ 입력 이미지 축소 상한 실측(후보별 처리 시간·결과 차이)과 제안 ④ 추출 결과·개발용 화면 연결, 지어낸 픽셀 테스트. **범위 밖:** 품질 기준 숫자(M3-3), 조명 보정과 판정(M3-2), 보정·필터 의심 측정 방법, 휴대폰 실기기(M4).

### M3-2 범위와 완료 기준 (승인 2026-10-23, 결정 로그 M3-2-범위·M3-2-Q1~Q8)
**범위:** ① 톤 ID를 구조에서 따온 이름으로 변경 ② 16톤 표시 이름 변경(9·14번)과 12톤 대응표·파생 함수 ③ 조명 보정 두 방식(core, **선형 색 공간**)과 회색 세계 가정용 기준 통계 측정(web, 색 편향과 같은 영역) ④ 16톤 판정과 1순위·2순위 ⑤ 신뢰도 계산 구조(영역 간 일관성 포함) ⑥ `ColorProfile` 생성 ⑦ 개발용 화면 연결, 지어낸 수치 테스트. **범위 밖:** 16톤 경계값·2순위 척도·신뢰도 가중치·보정 방식 선택·보정 한도 숫자(M3-3), 대비를 판정에 넣을지 비교(M3-3), 정밀 모드(M5), 결과 화면(M4), 검출 재시도(M4 후보), 머리카락·피부 영역 수정(M3-3, 13).

| # | 완료 기준 |
|---|---|
| 1 | 9번·14번 표시 이름과 4계절이 바뀌고, **16톤 전부 "4계절 = 이름 앞글자"** (테스트). `configVersion`을 올림 |
| 2 | 12톤 대응표가 설정에 있고 파생 함수가 있음. **16톤이 모두 대응됨, 16톤과 12톤의 계절이 같음, 12톤 12개가 모두 쓰임**. "확신 낮음"(4·14번)은 **설정에만** 있고 `ColorProfile`에는 없음. 2순위 12톤은 `tone16_second`에서 같은 함수로 계산(`tone12_second` 필드 없음) (테스트) |
| 3 | 조명 보정 두 방식이 core에 있고 숫자만 입력받음. 방식은 설정에서 고르고, **설정이 비어 있으면 "미설정" 오류**. "보정 안 함"은 값이 그대로, "회색 세계 가정"은 지어낸 편향을 없앰. **보정은 선형 색 공간에서** (테스트) |
| 4 | 회색 세계 가정용 기준 통계 측정 함수(web 순수 함수)가 **색 편향 측정과 같은 영역**(얼굴·목 밖)을 쓰고, 지어낸 픽셀 테스트 통과. 기준 영역이 작으면 "보정 안 함"으로 대체. 색 편향 측정과의 관계를 02에 기록 |
| 5 | 16톤 판정: 경계값이 비면 "미설정" 오류. **경계와 같은 값은 "이상" 쪽**. 16칸 모두 나올 수 있음 (테스트) |
| 6 | 2순위는 **항상 1순위의 이웃**(한 축만 한 칸 차이). 축별 척도([미정] 설정값)로 나눈 거리가 가장 작은 축을 고르고, **동점이면 웜/쿨 > 명도 > 채도** (테스트). 그림을 02에 기록 |
| 7 | 신뢰도 구조: 02의 다섯 요소로 0~1을 계산. **가중치가 비면 "미설정" 오류**. 대비와 "12톤 확신 낮음"은 넣지 않음 (테스트) |
| 8 | `ColorProfile` 생성: 품질 결과가 "실패"면 만들지 않음, `qualityFlags`에는 경고 코드만, `createdAt`은 밖에서 받음(core는 시계를 쓰지 않음). **좌표·얼굴 측정값이 들어가지 않음** (O-2, 테스트) |
| 9 | **같은 입력이면 같은 결과** (결정성 테스트) |
| 10 | **대비 값을 바꿔도** 1순위, 2순위, 4계절, 12톤, 신뢰도가 그대로이고 `axes.contrast`만 바뀜. 대비가 `null`이어도 정상 (테스트) |
| 11 | **색 편향을 못 재도** 두 보정 방식 모두에서 `ColorProfile`이 만들어짐 (테스트) |
| 12 | 개발용 화면에 두 보정 방식의 특징값을 나란히 보여 주고, 판정은 "미설정"으로 표시. 배포본 제외 유지, 진단 중 외부 요청 0건 |
| 13 | 실제 사진 수치 커밋 0건, 새 패키지 없음(생기면 11에 기록). Windows `npm run check` 통과, 승인 후 push 때 리눅스 CI 통과 |
| 14 | **톤 ID ↔ 축 위치(계열·명도·채도) 일치, 16개 ID 중복 없음, 표시 이름을 바꿔도 ID는 그대로** (테스트) |
| 15 | **보정 한도 초과, 기준 영역이 작을 때, 기준 영역을 못 잴 때** 각각 "보정 안 함 + `lighting_fallback`"이고 **신뢰도가 낮아짐** (테스트). [해석 확인 대기] 승인 문구의 세 번째 경우는 "보정 사용 안 함에서"였다. 설정에서 "보정 안 함"을 고른 경우는 대체가 아니므로 `lighting_fallback`을 넣지 않고, "회색 세계 가정인데 기준 통계가 없는 경우"로 해석했다 |
