# 07. 마일스톤과 에이전트 작업 규칙 (14)

## 에이전트 규칙
| ID | 규칙 |
|---|---|
| G-1 | 작업 전에 해당 섹션을 읽는다. **모순이나 빈틈을 발견하면 구현을 멈추고 기획자에게 보고** |
| G-2 | 한 마일스톤은 작게 끝낸다. **완료 기준은 착수 시 에이전트가 제안하고 기획자가 승인** |
| G-3 | `packages/core` 로직은 "추출된 색 수치" 입력 샘플로 만든 **자동 테스트** 필수 |
| G-4 | 새 패키지는 이유와 라이선스 기록. 비상업 라이선스 금지 |
| G-5 | 시크릿 파일 접근·출력, 코드 내 비밀 하드코딩 금지 |
| G-6 | 서비스 이름, UI 문구, AI 고지 문구는 한 곳(설정/문구 파일)에서 관리 |
| G-7 | 스위치, 쿼터, 예산 차단기를 우회하는 코드 금지 |
| G-8 | [확인필요] 항목은 구현 전 공식 문서로 확인하고 결과 기록 |
| G-9 | 기획 결정이 필요한 사안은 추정으로 진행하지 않고 질문 |
| G-10 | 변경이 지침서에 영향을 주면 갱신안과 결정 로그 항목을 함께 제안 |

## 1단계 마일스톤 (S 작음 / M 보통 / L 큼)
| # | 내용 | 크기 |
|---|---|---|
| M0 | 모노레포 뼈대, 비밀 유출 방지, 디자인 토큰, noindex | S |
| M1 | core: 색 계산, 타입(`ColorProfile` 등), `tone-config` 틀, 테스트 — **범위는 M1 착수 때 다시 제안** (뼈대에 이미 있는 타입·`tone-config` 틀·기본 색 계산과 테스트는 제외, 결정 로그 M0-8) | M |
| M2 | core: 품질 검사 규칙 + 테스트 | M |
| M3 | web: 얼굴 영역 추출기 + 분석 파이프라인 + 16톤 판정 (sRGB 정규화, EXIF 회전 포함) | L |
| M4 | web: 진단 화면 흐름 (촬영, 업로드, 품질 결과, 결과, 인앱 브라우저 안내) | L |
| M5 | 정밀 모드, 가상 드레이핑, 결과 카드 저장·공유 | M |
| M6 | Supabase 스키마 + RLS + 로그인 3종 | M |
| M7 | 피드백, 이력, 대표 진단, 마이(동의 관리, 탈퇴·삭제) | M |
| M8 | 서버 계층: `canUse`, `usage_events`, 크레딧 장부, 스위치, 예산 차단기 | L |
| M9 | 코디: 프롬프트, 팔레트 검증, 화면 | L |
| M10 | 16톤별 정적 콘텐츠 (AI 초안 → 사람 검수), 병행 가능 | M |
| M11 | 처리방침, 약관, AI 고지, 운영 체크리스트 | M |
| M12 | 지인 테스트 준비(배포, 백업 규칙, 점검) | S |

M3의 기준값과 품질 검사 수치는 샘플 사진으로 1차 설정하고, 지인 피드백으로 이후 튜닝한다.
v1.1 변경(M3 직후 정확도 점검 관문, M7 후 중간 공개)은 **승인됨**, `12-v1.1-changes.md` 참고.
