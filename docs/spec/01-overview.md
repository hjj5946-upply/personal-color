# 01. 개요·이름·불변 원칙·로드맵·아키텍처

## 개요
| 항목 | 내용 |
|---|---|
| 서비스 | **퍼코디** = 퍼스널컬러 진단 + AI 코디. 한 서비스 안의 **두 테마** |
| 사용자 | 10~40대 여성 약 70%, 남성 약 30%. **모든 기능은 성별 무관.** 개인 사용자 대상 |
| 가입 연령 | 전체 **만 14세 이상 체크**, 가상 피팅은 **만 19세 이상 체크** |
| 운영 | 1인 (기획·설계·PM 본인 + Claude Code 에이전트 개발). 사이드 프로젝트, 일정 여유 |
| 초기 사용 | 본인과 지인, 무료, 웹(PC/모바일). GitHub 주소로 공유 |
| 앱 | 설계는 처음부터 포함, 구현은 3단계 |
| 수익화 | 크레딧(건별) + 구독, 광고, 쇼핑몰 제휴 수수료. **설계는 하되 초기에는 OFF** |
| 사업자 | 사업자등록증 보유. 결제 전 확인 사항은 08 문서 |

**차별점:** ① 진단 결과가 코디의 입력이 되는 연결 구조 ② 신뢰도·2순위·한계를 숨기지 않는 솔직한 결과 ③ 진단 사진이 서버로 나가지 않는 브라우저 내 처리 ④ 옷 색이 내 팔레트와 맞는지 점수로 보여주는 옷 색 매칭

**하지 않는 것:** 얼굴로 사람을 식별·인증하기 / 의학적 진단 / 진단 사진의 서버 저장 / 쇼핑몰 상품 이미지 수집·저장 / 오픈소스 모델 직접 운영(셀프호스팅) / 1단계의 결제·광고·제휴 활성화

## 서비스 이름
- 한글 **퍼코디** [확정]. 영문 **Percody** [기본값]. 태그라인 "내 톤에 맞는 색, 코디까지 한 번에" [가칭].
- **N-1** 코드·패키지·DB·환경변수에 서비스 이름을 넣지 않는다. 내부 코드명(`personal-color`, `core`, `web`)을 쓴다.
- **N-2** 화면에 보이는 서비스 이름은 `SERVICE_NAME` 설정 한 곳(한글/영문/태그라인)에서만 읽는다.
- **N-3** 이름 중복(도메인, 앱 스토어 이름, 상표)은 **아직 확인하지 않았다.** 3단계 전에 확인(상표는 전문가).
- **N-4** GitHub 저장소 이름을 바꾸면 공유 주소가 달라진다. 지인에게 주소를 공유하기 전에 정한다.
- **N-5** 존재가 확인된 기존 서비스 이름(아이컬러, 코콘, 마이컬러, Dressika, Clad, 에이클로젯)과 혼동되는 표기는 쓰지 않는다.

## 불변 원칙
| ID | 원칙 |
|---|---|
| O-1 | 진단 사진은 **서버로 보내지 않는다.** 비로그인 체험 결과의 브라우저 임시 저장에는 **수치와 톤 결과만** 넣고, 사진·이미지 데이터·얼굴 좌표는 절대 넣지 않는다. 가상 피팅 사진은 **별도 동의 후에만 외부 업체로 보내고 우리 서버에는 저장하지 않는다.** |
| O-2 | 얼굴 데이터를 **식별, 인증, 얼굴 비교에 쓰지 않는다.** 랜드마크 좌표, 얼굴 특징값은 **어디에도 저장하지 않는다.** |
| O-3 | 비용이 드는 기능은 반드시 `canUse()`와 **전체 예산 차단기**를 거친다. |
| O-4 | 수익화 기능은 스위치 OFF일 때 **화면에서 숨기고 서버도 거부**한다. |
| O-5 | 판정·추천 로직은 `packages/core`에 두고 UI, 브라우저 API에 의존하지 않는다. |
| O-6 | 기준값은 설정 파일로 분리하고 결과에 `configVersion`을 남긴다. |
| O-7 | AI는 **우리 팔레트 안에서만** 색을 고르고, 출력은 반드시 검증한다. |
| O-8 | **호스팅 독립 3계층**(프런트 / 서버 로직 / Supabase). 프런트 호스팅을 바꿔도 기능이 같아야 한다. |
| O-9 | 저장소는 **퍼블릭**이다. 코드와 커밋 이력에 비밀이 없어야 한다. |
| O-10 | 결과는 단정하지 않는다. 신뢰도, 2순위, 한계를 보여준다. |
| O-11 | 생성형 AI 사용을 **사전 고지**하고, AI 생성물은 **표시**한다. |
| O-12 | 탈퇴하면 개인에 연결된 데이터를 **전부 삭제**한다. |

## 단계 로드맵
| 단계 | 내용 | 사용자 |
|---|---|---|
| **1단계** | 웹: 진단 + 코디 + 로그인 + 피드백 + 비용 보호/스위치 구조 | 본인과 지인, 무료 |
| **2-1단계** | 옷 색 매칭 (서버 비용 0원) | 동일 |
| **2-2단계** | 이미지 생성형 가상 피팅 (외부 API, 만 19세 이상) | 동일 |
| **3단계** | 앱(RN), 결제·광고·제휴 ON, 호스팅 재결정, 전문가 검토 | 점진 공개 |
| **4단계** | 실시간 카메라 피팅 (시험 제작 후 결정) | 점진 공개 |

**1단계 포함:** 진단(촬영/앨범, 품질 검사, 정밀 모드, 16톤 결과, 가상 드레이핑, 결과 카드 저장·공유, 피드백) / 코디(입력 4가지, 3벌 결과, 실루엣+색칩, 피드백) / 소셜 로그인 3종 / 마이(이력, 동의 관리, 탈퇴) / 크레딧 원장·`canUse`·스위치·예산 차단기 / 간이 처리방침·약관·AI 고지

**1단계 제외:** 사진 N일 보관, 옷 색 매칭, 가상 피팅, 앱, 결제·광고·제휴, 마케팅 발송, 날씨 연동, 체형·예산 입력, 외부 분석 도구

## 아키텍처와 기술 스택
```
repo (모노레포, 퍼블릭)
├ apps/web             Next.js(TypeScript). 정적 내보내기 호환 (API Routes, 서버 전용 기능 사용 금지)
├ apps/api             서버 로직 (1단계 후보: Supabase Edge Functions) [확인필요]
├ apps/mobile          3단계 (Expo/React Native)
├ packages/core        색 계산, 품질 검사, 톤 판정, 코디 검증, 과금·쿼터, 공급자 인터페이스
├ packages/design-tokens  디자인 토큰 JSON (웹·앱 공유)
└ docs                 지침서 등
```
| 영역 | 선택 |
|---|---|
| 프런트 호스팅 | 1단계 GitHub Pages(공개 저장소, 비상업, 정적만 가능). **3단계 전 재결정** (수익화 시 Pages, Vercel 무료 플랜 모두 상업 사용 제한) |
| DB·인증·저장소 | Supabase (무료 플랜: DB 500MB, 파일 1GB, 7일 비활동 시 일시정지, 다운로드 가능한 백업 없음) [가격·한도는 도입 시 재확인] |
| 로그인 | 카카오, 구글, 네이버. 애플은 앱 단계. 네이버는 별도 연동이 필요할 수 있음 [확인필요] |
| AI | Claude API(텍스트만, **서버 계층에서만** 호출). 모델은 구현 직전 최신 문서에서 확인 |
| 얼굴 영역 추출 | 웹: 오픈소스 얼굴 랜드마크(MediaPipe 등) 후보. 앱 호환은 3단계에서 검증 [확인필요] |
| 가상 피팅 | 외부 API, `TryOnProvider` 인터페이스로 추상화. 업체는 2-2단계 착수 시 비교 테스트 |
| 결제 | `PaymentProvider` 인터페이스(웹 PG / 앱 스토어). 업체는 3단계에 선정 |
