# 06. UX/UI 가이드 (10)

- **원칙:** 색이 주인공(UI는 무채색) / 솔직한 결과 / 한 화면 한 과제 / 모바일 우선 / 과장 금지
- **색 판단 영역(결과, 팔레트, 드레이핑)은 밝은 중립 배경 고정**, 다크 모드여도 유지.
- **토큰(초안):** 배경 `#FFFFFF`/`#F7F7F8`, 구분선 `#EDEDEF`, 본문 `#3A3A40`, 강조 `#111114`, 보조 `#6B6B73`(흰 배경 5.28:1, `#F7F7F8` 배경 4.93:1. 이전 `#8E8E96`은 3.25:1로 AA 미달), **글자색 토큰은 모든 배경 토큰에서 4.5:1 이상**(`packages/design-tokens/contrast.test.ts`가 검사), **포인트=검정(무채색)**, 모서리 12~16px, 간격 8px 단위, 그림자 최소. 글꼴 Pretendard 후보([확인필요] 라이선스). 토큰은 `packages/design-tokens/tokens.json` 하나로 웹·앱 공유.
- **내비게이션:** 하단 탭 4개 **[홈 / 진단 / 코디 / 마이]**. 2단계 기능은 별도 탭 없이 진단·코디 안에 스위치로 나타남. PC는 상단 메뉴 + 중앙 컬럼
- **1단계 화면:** 홈, 진단 시작, 촬영 가이드·카메라, 업로드 안내, 품질 결과, 분석 중, **진단 결과**, 드레이핑, 결과 카드, 피드백, 코디 입력, 코디 생성 중, **코디 결과**, 코디 피드백, 로그인, 마이, 한도·점검 안내
- **카피:** "~해요" 체, 가능성의 언어("~에 가까워요"), 한계는 한 줄로 명확히, 실패 안내는 "이유 한 문장 + 해결법 한 문장". 문구는 한 곳에서 관리.
- **스위치 OFF 기능은 아예 숨긴다.** ("준비 중" 표시 금지) 색칩에는 색 이름 병기.
- 한도·예산 도달 시 원인을 숨기지 않고 안내.
- Figma 시안은 기획자가 요청할 때만 시작한다.
